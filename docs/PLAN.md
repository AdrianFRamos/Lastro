# LASTRO — Hackathon Implementation Plan

**Period:** September 19 to October 12, 2026  
**Objective:** deliver physical, cryptographic, and on-chain proof of persistent identity and verifiable custody for cattle.

---

# 1. Delivery thesis

The hackathon must prove a complete flow:

```text
physical asset
→ observed physical identification
→ evidence signed by the Station
→ custodian authorization
→ canonical state on Solana
→ independent verification
```

The core property is:

> **The physical identifier may change without replacing the AnimalID, and only a transition compatible with the current canonical state may advance history.**

The delivery does not claim biological identity, legal ownership, regulatory compliance, or absolute truth about the physical world.

---

# 2. Closed scope

There are only three domain operations:

```text
ORIGIN
TRANSFER
REIDENTIFY
```

The hackathon must prove:

```text
P1  Real RFID observed by physical hardware
P2  Station binds the observed RFID to transition context and signs the resulting StationEvent
P3  Current custodian authorizes the transition
P4  Solana maintains a single canonical state per AnimalID
P5  AnimalID persists through RFID replacement
P6  Third party verifies history without trusting the backend verdict
```

Any feature that does not strengthen P1–P6 stays out.

---

# 3. Physical identity

Each demo animal has:

```text
AnimalID            persistent logical identity
RFID                replaceable electronic identifier
visual_recovery_id  physical visual recovery identifier
```

Rules:

```text
AnimalID != RFID != visual_recovery_id
```

RFID and the visual identifier must be on **separate physical elements**.

Recovery:

```text
RFID lost         → locate through visual_recovery_id
visual lost       → lookup by current RFID hash when that hash is already available
                    (standalone physical reading for recovery is outside the hackathon core)
both lost         → physical identity is UNRESOLVED in the hackathon
```

`visual_recovery_id`:

- stays off-chain;
- locates the correct record;
- does not authenticate the animal;
- does not replace the Station;
- does not replace the custodian wallet;
- does not participate in canonical state.

The hackathon does not implement livestock-management records. Birth date, sex, breed, weight, management, and vaccines are out of scope.

---

# 4. Identifiers and hashes

## AnimalID

```text
32 random bytes
```

Generated by the backend with a CSPRNG. Never derived from RFID.

## RFID

The reader parser produces one canonical representation.

```text
rfid_hash = SHA-256("LASTRO_RFID\0" || canonical_rfid)
```

The observed canonical value is preserved in the evidence package so it can be recomputed.

## StationID

```text
station_id = SHA-256("LASTRO_STATION\0" || compressed_p256_pubkey)
```

The compressed P-256 public key is 33 bytes.

## Event hash

```text
event_hash = SHA-256(StationEvent bytes)
```

---

# 5. StationEvent

Fixed binary format of **276 bytes**.

```text
magic                 [4]      "LSTR"
version               u8       1
action                u8       1=ORIGIN, 2=TRANSFER, 3=REIDENTIFY
reserved              [2]      zero

deployment_id         [32]
animal_id             [32]
station_id            [32]

event_sequence        u64_le
identity_revision     u32_le

previous_event_hash   [32]

old_rfid_hash         [32]
new_rfid_hash         [32]

from_custodian        [32]
to_custodian          [32]
```

Total:

```text
4 + 1 + 1 + 2
+ 32 + 32 + 32
+ 8 + 4
+ 32
+ 32 + 32
+ 32 + 32
= 276 bytes
```

The event does not include:

```text
GNSS
physical timestamp
weight
temperature
documents
geofence
compliance flags
livestock-management data
visual_recovery_id
```

# 6. Event semantics

## ORIGIN

```text
event_sequence        = 1
identity_revision     = 1
previous_event_hash   = zero
old_rfid_hash         = zero
new_rfid_hash         = observed RFID
from_custodian        = zero
to_custodian          = Wallet A
```

Requires a previously nonexistent AnimalID, a valid Station, and Wallet A signature.

## TRANSFER

```text
event_sequence        = current + 1
identity_revision     = current
previous_event_hash   = current.last_event_hash
old_rfid_hash         = current.current_rfid_hash
new_rfid_hash         = current.current_rfid_hash
from_custodian        = current.current_custodian
to_custodian          = destination
```

The Station physically rereads the current RFID. `from_custodian` signs the transaction.

## REIDENTIFY

```text
event_sequence        = current + 1
identity_revision     = current + 1
previous_event_hash   = current.last_event_hash
old_rfid_hash         = current.current_rfid_hash
new_rfid_hash         = newly observed RFID
from_custodian        = current.current_custodian
to_custodian          = current.current_custodian
```

Flow:

```text
locate AnimalID through visual_recovery_id
→ Station reads new RFID
→ Station signs
→ current custodian authorizes
→ Solana updates the binding
```

`old_rfid_hash` comes from canonical state. The old RFID does not need to be physically present during reidentification.

# 7. Station signature

The Station uses:

```text
ECDSA P-256
SHA-256
signature = r || s     64 bytes
pubkey                  33 bytes SEC1 compressed
low-S
```

Cryptographic flow:

```text
StationEvent bytes
→ SHA-256
→ ECDSA P-256
→ signature64
```

Rust, C, TypeScript, and the transaction builder must produce/verify the same vectors.

The private key starts as a development key. eFuse is introduced only after the complete flow is stable.

Claim allowed only after a real eFuse test:

```text
hardware-backed Station key
```

Without that gate, use only:

```text
device-signed P-256 evidence
```

# 8. Canonical state on Solana

## ProtocolConfig

```text
authority
deployment_id
station_pubkey33
```

One deployment and one Station are sufficient for the hackathon.

```text
ProtocolConfig PDA = ["config", deployment_id]
```

## AnimalState

```text
animal_id
current_rfid_hash
current_custodian
identity_revision
event_sequence
last_event_hash
```

```text
AnimalState PDA = ["animal", deployment_id, animal_id]
```

`event_sequence` belongs to the AnimalID; it is not a global Station counter.

## RfidBinding

Recovery through current RFID requires that an `rfid_hash` cannot simultaneously be the current binding of two `AnimalID` values. The program maintains a separate canonical index:

```text
RfidBinding
- animal_id
- rfid_hash
- status  ACTIVE | RETIRED

RfidBinding PDA = ["rfid", deployment_id, rfid_hash]
```

`ORIGIN` creates the first `ACTIVE` binding. `REIDENTIFY` marks the old binding `RETIRED` and creates a new `ACTIVE` binding in the same transaction. The program does not close retired bindings during the hackathon; therefore, an RFID that already participated in canonical history cannot be silently reused by another animal.

## On-chain rules

Solana must reject:

```text
duplicate ORIGIN
Station different from the registered Station
missing or invalid signature
signed message different from the executed event
old or skipped sequence
wrong previous_event_hash
wrong identity_revision
wrong custodian signer
RFID incompatible with current state
new RFID already known by another RfidBinding
old RFID used after REIDENTIFY
replay of a consumed event
```

The canonical sources are `AnimalState` for current animal state and `RfidBinding` for physical-binding uniqueness/history. PostgreSQL is only a projection.

# 9. P-256 ↔ Lastro program binding

The transaction uses:

```text
Instruction 0
Secp256r1 precompile
- signature64
- station_pubkey33
- message references the StationEvent bytes in Instruction 1

Instruction 1
Lastro program
- event: [u8; 276]
```

The precompile receives the **raw 276 StationEvent bytes** as its message. Do not send `event_hash` as the message, which would cause double hashing.

The program reads `sysvar::instructions` and verifies:

```text
expected precompile is present
pubkey == registered Station
message points exactly to the executed StationEvent
message length == 276
offsets and instruction indexes are correct
event_hash corresponds to the processed bytes
```

The builder requires real serialization/offset tests. The binding is complete only when valid and adversarial cases pass in a real transaction.

# 12. Firmware

Minimum structure:

```text
firmware/station/
├── CMakeLists.txt
├── sdkconfig.defaults
├── main/
│   ├── app_main.c
│   ├── station.c/.h
│   ├── rfid.c/.h
│   ├── event.c/.h
│   ├── signer.c/.h
│   └── transport.c/.h
└── tests/
```

Flow:

```text
COMMAND
→ read real RFID
→ canonicalize
→ build StationEvent
→ sign
→ EVENT_READY
```

The Station never receives `new_rfid_hash` from the backend. The new hash originates from the physical read.

Serial framing:

```text
magic | type | length | payload | crc32c
```

Messages:

```text
COMMAND
EVENT_READY
ACK
ERROR
```

`COMMAND` contains the expected transition context. `EVENT_READY` returns:

```text
capture_id
event_bytes[276]
observed_rfid
station_pubkey33
station_signature64
```

There is no complex persistent journal on the Station. If power fails before Agent persistence, the capture is repeated.

# 15. Solana program

Instructions:

```text
initialize
origin
transfer
reidentify
```

Rules:

### initialize

Creates `ProtocolConfig` with `deployment_id` and authorized Station.

### origin

```text
AnimalState does not exist
sequence = 1
revision = 1
predecessor = zero
old RFID = zero
to_custodian signer
valid Station signature
```

### transfer

```text
sequence = current + 1
revision = current
predecessor = current.last_event_hash
RFID = current RFID
from = current custodian
from signer
valid Station signature
```

Updates custodian, sequence, and last_event_hash.

### reidentify

```text
sequence = current + 1
revision = current + 1
predecessor = current.last_event_hash
old RFID = current RFID
new RFID != current RFID
from = to = current custodian
current custodian signer
valid Station signature
```

Updates current_rfid_hash, revision, sequence, and last_event_hash.
